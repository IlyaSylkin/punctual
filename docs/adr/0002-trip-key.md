# ADR-002. Составной ключ рейса и дедупликация по содержимому

**Статус:** принято, 19.09.2026

## Контекст

В фидах HSL отсутствуют `trip_id` и `stop_sequence`. `header.timestamp` меняется
почти на каждый запрос: 19 034 уникальных значения за 26 часов при периоде
обновления 11 секунд.

## Решение

Ключ рейса — `city + route_id + direction_id + start_date + start_time`.
`trip_id` хранится дополнительным полем там, где источник его отдаёт.

Дедупликация входящих ответов — по хэшу тела; внутри снимка состояние машины
сравнивается по паре `(vehicle_id, ts)`.

## Альтернативы

**`trip_id` как ключ** — отвергнуто: у HSL его нет. Кроме того,
[документация HSL](https://hsldevcom.github.io/gtfs_rt/) прямо рекомендует
составной ключ, поскольку `trip_id` в статике нестабилен.

**Синтетический внутренний ключ** — отвергнуто: делает данные несопоставимыми
с источником и ломает проверку отдельного случая.

**Дедупликация по `header.timestamp`** — отвергнуто измерением: заголовок не
отражает изменение содержимого.

## Проверка

Коллизии ключа внутри одного снимка должны быть нулевыми. Проверено: 0 из 1478
рейсов. Повторять при подключении нового источника.

## Следствия

`start_time` хранится строкой: ночные рейсы имеют отправление вида `25:30:00`.
