# ADR-010. Резолвер — процесс с минутным циклом

**Статус:** принято, 19.09.2026

## Контекст

Факт прибытия устаканивается за две минуты (ADR-003). Реагировать быстрее
бессмысленно: значение ещё может измениться.

## Решение

Резолвер — постоянный процесс с циклом раз в 60 секунд. Берёт из `arrivals`
записи, не менявшиеся ≥ 2 минут и ещё не разрешённые; достаёт историю прогнозов;
для каждой корзины находит **действовавший** прогноз; пишет строку в `errors`.

## Альтернативы

**DAG в Airflow** — отвергнуто: накладные расходы на каждый запуск, планировщик
рассчитан на часовые и суточные интервалы.

**Потоковый потребитель Kafka** — отвергнуто: задержка в две минуты всё равно
обязательна, поэтому потоковая обработка не даёт выигрыша. Резолвер ходит прямо
в ClickHouse.

**Раскладывать сами изменения прогнозов по корзинам их публикации** — отвергнуто:
смещает выборку. Метрика отвечает на вопрос «насколько точен прогноз, который
видит пассажир», а пассажир видит **последний опубликованный**. 11.4% пар не
меняются ни разу и дали бы одну строку вместо участия во всех корзинах.

## Проверка

Отставание резолвера от потока фактов не должно расти. Метрика: возраст самого
старого неразрешённого факта. Растёт устойчиво — цикл не справляется.

## Следствия

Живая лента в демо отстаёт на две-три минуты. Это подписывается на странице.

Ошибка хранится **со знаком**: допуски несимметричны, «пришёл раньше» надо
отличать от «пришёл позже».
