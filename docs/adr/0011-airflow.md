# ADR-011. Airflow для роллапов и backfill

**Статус:** принято, 19.09.2026

## Контекст

Часть работы идёт по расписанию, а не по событиям: обновление расписания GTFS,
почасовые агрегаты, суточные артефакты моделей, прогоны экспериментов.

Настоящая потребность — **backfill**: после исправления ошибки в расчёте надо
пересчитать окно за прошлое, не останавливая приём.

## Решение

Airflow с `LocalExecutor`. DAG: обновление GTFS static, почасовые агрегаты,
суточные профили и таблица поправок, прогон эксперимента по требованию.

## Альтернативы

**Крон плюс скрипты** — закрывает запуск по расписанию. Отвергнуто: нет истории
запусков, нет повторов при сбое, нет зависимостей между задачами и нет backfill.
Всё это дописывается, но это несколько сотен строк собственного планировщика.

**APScheduler** — легче, но без backfill и истории.

**Dagster, Prefect** — современнее, но заметно менее распространены на рынке.

## Проверка

Backfill обязан состояться на практике: исправление логики и пересчёт окна
минимум за неделю. Если за весь проект ни разу не понадобился — **фиксируем, что
технология не оправдалась**, крона хватило бы.

## Следствия

Около 2 ГБ памяти на планировщик, веб-сервер и базу метаданных — примерно треть
VPS. База метаданных заводится внутри существующего Postgres.

Задачи обязаны быть идемпотентными: повторный запуск за тот же интервал должен
давать тот же результат, то есть сначала удалять свой прошлый результат за этот
интервал, потом писать новый.
