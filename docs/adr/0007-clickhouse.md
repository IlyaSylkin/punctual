# ADR-007. ClickHouse для истории

**Статус:** принято, 19.09.2026

## Контекст

Объём по одному городу — **341 млн строк в месяц**, около 1.4 млрд за четыре
месяца. Основные запросы: агрегаты по нескольким колонкам из десяти за периоды
в месяцы, с группировкой по маршруту, часу и дню недели.

## Решение

ClickHouse как хранилище истории. Postgres остаётся для справочников GTFS static
и пользовательских данных.

## Альтернативы

**Только Postgres** — отвергнуто: на сотнях миллионов строк строковое хранение
поднимает с диска все колонки, включая не участвующие в запросе. Ожидается
перелом с сотен миллисекунд на десятки секунд.

**Только ClickHouse** — отвергнуто: справочники обновляются целиком раз в
несколько недель и требуют транзакций и внешних ключей.

## Проверка

Бенчмарк **кривой**, а не одной точкой: один и тот же агрегат на 10 / 50 / 100 /
300 млн строк в обеих СУБД. Ценность в том, где именно Postgres переламывается.
**Если Postgres не переломится — решение признаётся неоправданным.**

## Следствия

Колоночное сжатие даёт больше, чем измеренные 2.9–3.2x для gzip поверх protobuf:
в колонке рядом лежат однородные значения. Фактический коэффициент проверить на
первых миллионах строк.
