# ADR-006. Хранятся изменения прогнозов, а не состояние

**Статус:** принято, 19.09.2026

## Контекст

HSL пересылает рейс целиком каждые 15 секунд, включая уже пройденные остановки:
около 1200 рейсов × 31 запись = 37.6 тыс. записей в снимке, **217 млн строк в
сутки** при хранении состояния на каждый момент.

Замер дрейфа: между соседними снимками прогноз не меняется в девяти случаях из
десяти (медиана 0, p90 0).

## Решение

Сохраняется строка только при изменении предсказанного времени. Прогноз на любой
момент восстанавливается как последняя запись с `published_at ≤ момент`.
Отдельно фиксируются появление и исчезновение прогноза.

Рейсы без единого прогноза (`NO_DATA` — завтрашнее расписание) отбрасываются на
приёме: −24% объёма без потерь, в тестовый набор они не попадают.

## Альтернативы

**Хранить состояние** — отвергнуто по объёму: 6.5 млрд строк в месяц.

**Срез на фиксированных горизонтах (20/15/10/5/2/1 мин)** — отвергнуто дважды:
теряет информацию и несовместимо с методикой TransitApp, которая требует
раскладывать по времени до фактического прибытия, а оно в момент публикации
неизвестно.

## Проверка

Измерено: 7.8 строки на пару вместо 72, выигрыш **9.3x**. Если среднее число
изменений на пару вырастет выше 20, решение теряет смысл и его надо пересмотреть.

## Следствия

Границы корзин становятся дешёвым решением: любую методику можно применить
задним числом к тем же данным.

`predicted_arrival = NULL` означает событие «прогноз исчез», а не отсутствие
данных.
