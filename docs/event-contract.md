# Контракт событий

Формат сообщений, которые `ingestor` публикует в Kafka.

Версия контракта: **1**. Редакция от 16.09.2026.
Источник числовых характеристик: [measurements.md](measurements.md).

## Топики

| Топик | Единица сообщения | Ключ | Объём |
|---|---|---|---|
| `vehicle.positions` | рапорт одной машины | `city:vehicle_id` | 6.6 млн сообщ./сут |
| `trip.updates` | рейс со списком остановок | `city:route_id:direction_id:start_date:start_time` | 6.9 млн сообщ./сут |

Единица `trip.updates` — рейс, а не остановка: на остановку вышло бы 2500
сообщений в секунду против 80. Удержание 48 часов со сжатием zstd занимает
около 12 ГБ на оба топика.

Ключ рейса составной, потому что `trip_id` в фидах HSL отсутствует. Там, где
источник его отдаёт, он передаётся отдельным полем. `city` входит в ключ везде:
идентификаторы машин, остановок и маршрутов между городами не уникальны.

## `vehicle.positions`

```json
{
  "v": 1, "city": "hsl",
  "route_id": "1550", "direction_id": 0,
  "start_date": "20260914", "start_time": "16:12:00",
  "trip_id": null, "vehicle_id": "1042",
  "ts": 1789397532, "ingested_at": 1789397535,
  "lat": 60.1699, "lon": 24.9384,
  "bearing": 90.0, "speed": 6.7,
  "stop_id": "1121455", "stop_sequence": null,
  "current_status": "STOPPED_AT"
}
```

| Поле | Тип | Обяз. | Заполнено | Отсутствие означает |
|---|---|---|---|---|
| `v` | int | да | — | — |
| `city` | str | да | — | `hsl`, далее другие города |
| `route_id` | str | да | 100% | — |
| `direction_id` | int | да | 100% | — |
| `start_date` | str | да | 100% | формат `YYYYMMDD` |
| `start_time` | str | да | 100% | местное время, допустимо `> 24:00:00` |
| `trip_id` | str | нет | **отсутствует** | у HSL не существует |
| `vehicle_id` | str | да | 100% | — |
| `ts` | int | да | 100% | время рапорта машины |
| `ingested_at` | int | да | — | время получения; `ingested_at − ts` = лаг приёма |
| `lat`, `lon` | float | да | 100% | — |
| `bearing` | float | нет | 100% | курс в градусах, 0 = север |
| `speed` | float | нет | 100% | м/с; скорость неизвестна (не ноль) |
| `stop_id` | str | нет | 99.3% | машина не привязана к остановке |
| `stop_sequence` | int | нет | 0% | восстанавливается из GTFS static |
| `current_status` | str | нет | 99.3% | `INCOMING_AT` / `STOPPED_AT` / `IN_TRANSIT_TO` |

Не передаются: `odometer`, `occupancy_status`, `multi_carriage_details`.

## `trip.updates`

```json
{
  "v": 1, "city": "hsl",
  "route_id": "1550", "direction_id": 0,
  "start_date": "20260914", "start_time": "16:12:00",
  "trip_id": null, "vehicle_id": null,
  "published_at": 1789397530, "ingested_at": 1789397535,
  "stops": [
    {"stop_id": "1121455", "stop_sequence": null,
     "arrival_time": 1789396443, "arrival_uncertainty": 0,
     "departure_time": 1789396461, "schedule_relationship": "SCHEDULED"},
    {"stop_id": "1121460", "stop_sequence": null,
     "arrival_time": 1789397890, "arrival_uncertainty": null,
     "departure_time": 1789397905, "schedule_relationship": "SCHEDULED"}
  ]
}
```

| Поле | Тип | Обяз. | Заполнено | Отсутствие означает |
|---|---|---|---|---|
| `published_at` | int | да | 100% | время расчёта прогноза агентством |
| `vehicle_id` | str | нет | нет | машина на рейс не назначена |
| `stops[].stop_id` | str | да | 100% | — |
| `stops[].stop_sequence` | int | нет | 0% | восстанавливается из GTFS static |
| `stops[].arrival_time` | int | нет | 77.8% | прогноза нет |
| `stops[].arrival_uncertainty` | int | нет | 43.1% | см. ниже |
| `stops[].departure_time` | int | нет | 77.8% | разница с прибытием = время стоянки |
| `stops[].schedule_relationship` | str | да | 100% | по умолчанию `SCHEDULED` |

`arrival_delay` не передаётся: пуст у обоих агентств. Отклонение от расписания
вычисляется из GTFS static.

### `arrival_uncertainty`

Значение поля означает разное в зависимости от города.

| Значение | Смысл у HSL |
|---|---|
| `0` | остановка пройдена: **фактическое время, не прогноз** |
| `null` | это прогноз |

У других источников то же поле означает оценку погрешности прогноза в секундах.
Семантика проверяется отдельно для каждого источника перед подключением.

Семантика HSL зафиксирована в их документации: *«uncertainty is set to 0 for
stops which the vehicle has passed»*.

Факт правится: 4.8% фактов получают ровно одну правку, 99.6% из них вперёд,
медиана +10 с, обычно в пределах минуты. **Потребители используют значение,
не менявшееся 2 минуты**, а не первое опубликованное.

## Правила приёма

**Дедупликация по хэшу тела ответа.** `header.timestamp` у HSL меняется почти на
каждый запрос и для дедупликации непригоден. Внутри снимка состояние машины
сравнивается по `(vehicle_id, ts)`.

**Рейс без единого `arrival_time` не публикуется.** Это завтрашнее расписание
(`NO_DATA`): такие рейсы отправляются в среднем через 35 часов, 95.7% не
получают прогноза в пределах суток. Отбрасывается рейс целиком — частичного
`NO_DATA` не встречается. Даёт −24% объёма топика.

**Ноль не подставляется вместо отсутствия.** `speed = 0` и `speed = null` —
разные значения, после подстановки неразличимы.

**Ingestor не вычисляет производных величин.** Фид невосстановим, вычисленное
пересчитывается. `stop_sequence` из GTFS static, скорость из разницы координат
там, где её нет в фиде, и изменения прогнозов вычисляют потребители.

**Событие отбрасывается только при отсутствии ключа или координат.** Остальные
поля — `null`. Доля отброшенных событий экспортируется метрикой и используется
в алерте.

**Валидация на обоих концах.** В топике одновременно находятся сообщения,
записанные разными версиями `ingestor`.

## Версионирование

Добавление необязательного поля версию не меняет.

Любое другое изменение увеличивает `v`. Потребители обязаны понимать все версии,
встречающиеся в пределах удержания топика (48 часов).

Поле не переиспользуется под другим смыслом. Переименование — новое поле плюс
удаление старого через две версии.

## Подключение второго города

Контракт рассчитан на несколько источников. При подключении меняются только
значения `city` и адаптер в `ingestor`; схема сообщения, ключи и правила приёма
остаются. Перед подключением проверяется состав полей источника: заполненность
и семантика `uncertainty` у разных агентств различаются.

## Вне контракта

Схемы таблиц описаны отдельно — [data-model.md](data-model.md).

Не определены и откладываются до кода: загрузка и версионирование GTFS static,
