# punctual

**Независимая оценка точности прогнозов прибытия городского транспорта.**

Транспортные агентства публикуют прогнозы прибытия каждые 10–15 секунд, но не
публикуют, насколько эти прогнозы сбываются. Проект измеряет это для Хельсинки
(HSL) и сравнивает официальный прогноз с альтернативными моделями на одном
наборе фактических прибытий, по одним правилам.

---

## Что измеряется

Не только средняя ошибка. Измеряется **её устройство**:

- **случайная она или систематическая** — есть ли смещение, которое можно
  вычесть, не имея никаких данных сверх публичных;
- **от чего зависит** — от горизонта, часа суток, дня недели, маршрута;
- **покрытие** — на какой доле прибытий прогноз вообще существует;
- **сравнение с альтернативами** — простое расписание, историческая статистика,
  прогноз агентства с поправкой на его систематическую ошибку.

Одно усреднённое число тут бесполезно: прогноз за минуту до прибытия и за
двадцать минут — разные задачи, и сравнивать их вперемешку нельзя.

---

## Результаты

**Предварительно.** Окно 3.5 часа одного дня, 141 775 прибытий. Для утверждений
о точности нужна история за месяцы — см. [Статус](#статус).

Точность официального прогноза HSL, корзины по времени до фактического прибытия:

| До прибытия | Средняя ошибка | p90 | В допуске |
|---|---:|---:|---:|
| 0–3 мин | **34 с** | 71 с | 93.9% |
| 3–6 мин | **52 с** | 103 с | 96.9% |
| 6–10 мин | **66 с** | 133 с | 96.6% |
| 10–15 мин | **81 с** | 165 с | 97.6% |
| 15–30 мин | 105 с | 219 с | — |
| 30+ мин | 149 с | 323 с | — |

В 15–16% случаев автобус приходит **раньше** обещанного — для пассажира это
хуже опоздания, потому что он не успевает.

### Две метрики расходятся в направлении

Средняя ошибка растёт с горизонтом — 34 секунды на трёх минутах, 81 на
пятнадцати. Доля прогнозов в допуске **тоже растёт** — 93.9% и 97.6%.

Обе цифры верны: допуск расширяется быстрее, чем растёт ошибка. По одной мере
прогноз на дальнем горизонте хуже втрое, по другой — лучше.

Отсюда требование к любому отчёту о точности: **доля точных прогнозов
бессмысленна без приложенной методики.** «96% прогнозов точны» не означает
ничего, пока не сказано, что считается точным.

Подробности и способ воспроизведения: [docs/measurements.md](docs/measurements.md).

## Метод, коротко

**Факт прибытия** берётся из фида: HSL помечает пройденные остановки полем
`uncertainty = 0`. Используется устоявшееся значение — не менявшееся две минуты.

**Корзины** — по времени до **фактического** прибытия, а не до предсказанного,
иначе модель может подыгрывать себе. Границы и допуски взяты из опубликованной
методики [TransitApp / IBI Group](https://github.com/TransitApp/ETA-Accuracy-Benchmark),
чтобы их нельзя было заподозрить в подгонке под результат.

**Три меры рядом:** средняя ошибка, доля в допуске и покрытие. Точность без
покрытия бессмысленна: модель, отвечающая на 10% самых лёгких случаев с ошибкой
20 секунд, не лучше отвечающей всегда с ошибкой 90.

**Разрешающая способность — 10 секунд.** Два независимых источника расходятся в
определении момента прибытия на 4 секунды медианно. Превосходство меньше десяти
секунд здесь заявлять нельзя, и проект этого не делает.

**Одни правила для всех моделей:** один набор событий, одно определение факта,
одна нарезка по корзинам. Модель предсказывает момент T только по данным,
существовавшим до T.

Подробно: [измерения и способ их воспроизвести](docs/measurements.md),
[решения с альтернативами](docs/adr/).

## Архитектура

```
GTFS-RT фиды HSL
  позиции (телеметрия)      прогнозы (операционная система)
        │                          │
        ▼                          ▼
   ┌────────────────────────────────────┐
   │             ingestor               │
   └─────────────────┬──────────────────┘
                     ▼
                  Kafka                  буфер: приём не зависит
                     │                   от доступности хранилища
        ┌────────────┴────────────┐
        ▼                         ▼
   ┌──────────┐            ┌──────────┐
   │   sink   │            │ resolver │   сводит прогноз с фактом,
   │ изменения│            │  ошибки  │   считает модели
   └────┬─────┘            └────┬─────┘
        ▼                       ▼
     ClickHouse ◄──────────── Airflow     профили и таблица поправок
        │
        ▼
     FastAPI → nginx → результаты и живое сравнение
```

Архитектура выведена из требований к измерению, а не выбрана заранее.
Три числа, которые её определяют:

- **фид эфемерен** — что не записано, потеряно навсегда; приём не может
  блокироваться на хранилище, отсюда буфер;
- **341 млн строк в месяц** — история за месяцы требует колоночного хранилища;
- **прогноз почти не меняется** (медиана дрейфа 0), поэтому хранятся изменения,
  а не состояние: 7.8 строки на пару вместо 72.

Полный разбор: [docs/event-contract.md](docs/event-contract.md).

## Запуск

Требуется [uv](https://docs.astral.sh/uv/). Python устанавливать не нужно.

```bash
git clone git@github.com:IlyaSylkin/punctual.git
cd punctual
make install    # окружение, зависимости, git-хуки
make check      # линтер, типы, тесты
```

Приёма данных пока нет — см. [Статус](#статус).

## Ограничения

**Измеряется отклонение не от реальности, а от заявленного эталона.** Момент
прибытия недоступен напрямую никому; за эталон берётся то, что публикует HSL.
Два независимых источника сходятся на 4 секундах — это граница доверия, а не
доказательство.

**Нельзя исключить общую логику.** Прогнозы и факты HSL приходят из одной
коммерческой системы (PubTrans), её кода нет. Если прогноз и факт выведены
общим кодом, измеренная ошибка занижена. Снаружи это не проверяется.

**Один город.** Все числа относятся к Хельсинки. Второй город добавляется
позже — и не ради объёма, а чтобы проверить, зависит ли выигрыш поправки от
качества исходного прогноза.

## Prior art

- [MBTA Arrival Prediction Accuracy](https://www.mbta.com/performance-metrics/arrival-prediction-accuracy)
  — агентство Бостона публикует точность своих прогнозов само, с собственными
  окнами допуска.
- [overdue](https://github.com/skyjafar-ds/overdue) — независимая обсерватория
  прогнозов MBTA и BART.
- [Caltrans GTFS-RT metrics](https://analysis.dds.dot.ca.gov/rt_stop_metrics/)
  — межоператорские метрики качества реального времени.
- [TheTransitClock](https://thetransitclock.github.io/) — открытый движок
  прогнозов, умеет сравнивать свою точность с системой агентства.
- [Assessing GTFS Accuracy](https://transweb.sjsu.edu/mctm/research/utc/Assessing-GTFS-Accuracy),
  Mineta Transportation Institute, 2024 — методика измерения временной точности.

Для Хельсинки ни публикации точности агентством, ни стороннего измерения найти
не удалось (поиск по-английски, по-русски и по-фински).
