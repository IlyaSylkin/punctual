# Вопросы, зафиксированные ДО захвата данных

Записано 14.09.2026, до начала суточного захвата. Список закрыт: новые вопросы
можно добавлять только отдельным разделом ниже, с датой, чтобы было видно, что
они появились после того, как данные увидели.

Причина такой дисциплины: за предыдущие дни три вывода пришлось отзывать —
ключ рейса в первом замере дрейфа, оценка объёма по дневному пику, трактовка
`NO_DATA`. Все три из-за того, что замер делался одним снимком и сразу
интерпретировался.

## Приём и объём

1. Период обновления каждого из 4 фидов — **распределение**, а не медиана.
2. Строк и байт **по часам суток**. Оценка 224M строк/мес для HSL посчитана по
   дневному пику и почти наверняка завышена.
3. Доля дубликатов при дедупликации по `(vehicle_id, vehicle.timestamp)`.
4. Доля «стоящих»: `timestamp` меняется, координаты нет (открытый вопрос Q2).
5. Реальный коэффициент сжатия на наших данных.

## Ключи и идентификация

6. Уникален ли ключ рейса `route_id + direction_id + start_date + start_time`.
   Есть ли коллизии внутри одного снимка и между снимками.
7. Повторяются ли остановки внутри одного рейса (кольцевые маршруты) — влияет
   на восстановление `stop_sequence` из GTFS static для HSL.
8. Как связать рейс из фида позиций с рейсом из фида прогнозов: у HSL в
   TripUpdates нет `vehicle`, в позициях нет `trip_id`.

## Факт прибытия

9. Не правится ли задним числом время у записей с `uncertainty = 0`.
   **На этом держится вся метрика.**
10. Скорость появления фактов по часам суток.
11. Расхождение между фактом из TripUpdates (`uncertainty = 0`) и
    `current_status = STOPPED_AT` из фида позиций (Q1, независимая проверка).
12. Переходят ли рейсы из `NO_DATA` в «с прогнозом» постепенно, по мере
    приближения отправления — можно ли отбрасывать такие записи на приёме.

## Прогнозы

13. Горизонт прогноза: распределение по числу остановок и по минутам.
14. Дрейф прогноза по горизонтам, с полным ключом рейса.
15. **Настоящий MAE официального прогноза HSL по горизонтам** — по фактам из
    фида, а не по прокси. Главное число проекта.

## Для схемы БД

16. Кардинальности: маршруты, направления, остановки, перегоны.
17. Размер строки и сжатие на реальных данных — уточнить оценку хранения.
