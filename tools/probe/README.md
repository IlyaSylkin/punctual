# Инструменты замера

Захват сырья GTFS-Realtime и анализ по нему. Всё, на чём построены числа в
[docs/measurements.md](../../docs/measurements.md), считается этими скриптами —
результаты можно перепроверить.

## Куда пишутся и откуда читаются данные

Каталог задаётся переменной `CAPTURE_DIR`, по умолчанию `./capture`:

```bash
export CAPTURE_DIR=/путь/к/данным
```

## Захват

```bash
python capture.py 26        # писать 26 часов
```

Опрашивает фиды позиций и прогнозов раз в 10 секунд,
сохраняет **только изменившиеся** ответы, дедуплицируя по хэшу тела.

Формат архива: повторяющиеся `[4 байта длины BE][protobuf]`, весь поток gzip,
почасовые файлы. Имя файла включает идентификатор запуска (`время-PID`) —
два процесса не могут писать в один файл.

Рядом пишется журнал метаданных JSONL: строка на каждый опрос, с временем,
кодом ответа, размером, `header.timestamp` и признаком сохранения. По нему
считаются пропуски и ошибки сети, не разжимая архивы.

## Чтение

`reader.py` — общая читалка. Терпит повреждённые и незакрытые архивы: отдаёт
всё до первой ошибки, дедуплицирует по `header.timestamp`.

## Анализ

Запускаются из этого каталога, читают `CAPTURE_DIR`. Окно задаётся списком
`HOURS` внутри скрипта — в опубликованных числах это окно указано в
[measurements.md](../../docs/measurements.md).

| Скрипт | На какой вопрос отвечает |
|---|---|
| `q_positions.py` | период обновления машины, доля дубликатов, доля стоящих, кардинальности, сжатие |
| `q_accuracy.py` | **точность официального прогноза**: MAE и доля в допуске по корзинам |
| `q_fact_stability.py` | правится ли факт прибытия задним числом |
| `q_prediction_changes.py` | сколько раз меняется прогноз за жизнь пары, выигрыш хранения изменений |
| `q_cross_feed.py` | связь двух фидов по ключу рейса, расхождение двух определений прибытия |
| `q_daily_profile.py` | объём и скорость появления фактов по часам суток |
| `q_field_inventory.py` | заполненность полей по обоим фидам |

`QUESTIONS.md` — список вопросов, **зафиксированный до захвата**, чтобы
результаты не подгонялись под вопросы.

## Не сохранено

Первичный отсев 215 фидов из каталога MobilityData делался разовым скриптом,
который не сохранился. Он относился к выбору города, а не к измерениям: его
результат — обоснование [ADR-001](../../docs/adr/0001-helsinki-first.md), и
перепроверить его без переписывания нельзя.

Все числа из `measurements.md` считаются скриптами выше.
